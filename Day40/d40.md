#### useId - Genereates a unique ID
- useId generates a unique id that you can use to connect related elements, especially form labels and inputs.
- This is mainly useful for accessibility and reusable components.
```tsx
import {useId} from "react";
function App(){
    const id = useId();
    return(
        <>
        <label htmlFor={id}>Name</label>
        <input id={id} type="text" />
        </>
    );
}
```
- id = useId() might generate an ID such as: `:r0:`
- htmlfor and id attributes both are referes to the same unique ID.

**Why not just write an ID?**
```tsx
<label htmlFor="name">Name</label>
<input id="name" type="text" />
```
- But imagine you create the same reusable component multiple times.
- If every component uses id as "name" then we can end up with duplicate IDs.
- useId() gives each component instance a unique ID.

**Reusable Component Example:**
```tsx
type InputProps = {
    label: string;
};

function InputField({label}: InputProps){
    const id = useId();

    return(
        <>
        <lable htmlFor={id}>{label}</label>
        <input id={id} text="text" />
        </>
    );
}
```
- Then we can reuse that component:
```tsx
import InputField from "./inputField";

function App(){
    return(
        <>
        <InputField label="Name" />
        <InputField label="Email" />
        </>
    );
}
```

**Multiple IDs from one**
- Sometimes a component needs several related IDs.
```tsx
const id = useId();
const inputId = `${id}-input`;
const descriptionId = `${id}-description`;
```
- Then:

```tsx
<lable htmlFor = {inputId}>Name</label>
<input id={inputId} area-describedby={descriptionId} />
<p id={descriptionId}>My name is Tharun kumar.</p>
```
- This is useful for accessible  forms.
- Don't use useId for list keys beacuse useId is not intended for generating list keys.
- For lists use your actual data's stable ID.
