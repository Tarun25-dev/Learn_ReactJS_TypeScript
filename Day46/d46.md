####  useSyncExternalStore
- useSyncExternalStore = It lets a react component safely subscribe to data that is managed outside react state.

**Why do we need this?**
```tsx
const [count, setCount] = useState(0);
```
- React controls the state.
- But sometimes data lives outside React.
- Like: Browser storage -> External store -> react component
- Imagine a store that contains: 
```text
theme
online/offline status
application settings
global external state
```
- React needs a way to subscribe to changes in that external data.
- Thats where useSyncExternalStore comes in.

**Basic structure:**
```tsx
const value = useSyncExternalStore(subscribe, getSnapshot);
```
- There are two important functions:
- 1. subscribe - Notify me whenever this external data changes.
- 2. getSnapshot - Give me the current value.

**Creating simple external store:**
```tsx
let count = 0;

const listeners = new Set<() => void>();

function subscribe(listener: () => void){
    listeners.add(listener);

    return () => {
        listeners.delete(listener);
    };
}

function getSnapshot(){
    return count;
}
```
- const listeners = new Set<() => void>(); 
- which creates a set called listeners and store inside function that must has no arguments and no useful value.
- set is a collection used to store unique values and which restricts duplicates.
- count -> external data.
- listeners -> components intrested in changes.

**Updating the store:**
```tsx
function increase(){
    count++;

    listeners.forEach(listener => {listener()});
}
```
- when count changes -> notify listeners -> react knows something changed -> component reads new snapshot.

**Connect it to react**
```tsx
function Counter(){
    const count = useSyncExternalStore(subscribe, getSnapshot);

    return <h2>Count: {count}</h2>;
}
```
- subscribe = listen for changes, if changes happens reacts knows that and immpediately updates values through Snapshot.

**Usecases:**
- External state-management libraries
- Browser APIs
- Custom stores
- Data that exists outside React
- Libraries that need React-safe subscriptions.

**useState VS useSyncExternalStore**
- React owns the state -> useState -> Component
- External store owns the state -> subscribe + getSnapshot -> useSyncExtrenalStore -> Component
