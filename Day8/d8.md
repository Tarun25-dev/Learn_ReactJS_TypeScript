#### Event Handling + Typescript
- Now we are moving into user interface
- We already learned functions in typescript so we will connect it to React events.

**Handling a click**
```tsx
function App(){
    function handleClick(){
        console.log("button Clicked");
    }
    return(
        <>
        <button onClick={handleClick}>Click Me</button>
        </>
    );
}

```
- {handleClick} = we are refering to the function itself, not calling it.
- onClick event decides when it call.
- Reacts calls handleClick when the user clicks the button.
- **Important:** If we write like this **onlick={handleClick()}** 
- That calls the function immediately while rendering.

**Passing an argument**
- Suppose you want to send a value:
```tsx
function App(){
    function handleClick(name: string){
        console.log(`Hello ${name}`);
    }
    return (
        <button onClick={() => handleClick("Tharun")}></button>
    );
}
```
**Typescript event types**
- This is where react + typescript becomes important.
- Suppose you have an input:
```tsx
function App(){
    function handleChange(event: ChangeEvent<HTMLInputElement>){
        console.log(event.target.value);
    }
    return <input onChange = {handleChange} />
}
```
- `event: ChangeEvent<HTMLInputElement>`:
- event is a parameter to the handleChange and it has the information of that event
- ChangeEvent<HTMLInputElement> this is a type of an event, that actually tells to typescript what type of event it is?
- that generic tells typescript which HTML element is involved.
- for onChange() event we use ChangeEvent<> and inside that event must be input element says to ts HTMLInputElement.
- If we dont use `event: ChangeEvent<HTMLInputElement>` then we must `import type {ChangeEvent} from "react".`
- After we use that import like: event: ChangeEvent
- that onChange returns object type info when it used we access that exact input value with `event.target.value`
- target refers to the element, here it is input element.
- value refers to that use changed that input value.

**Example with a button event**
```tsx
function App(){
    function buttonClick(event: MouseEvent<HTMLButtonElement>){
        console.log(event.currentTarget);
    }
    return <button onClick = {buttonClick}>Click</button>;
}
```
- event.currentTarget = which element is handling my event?

**event.target VS event.currentTarget**

- Suppose:
```html
<div onClick={handleClick}>
    <button>Apple</button>
    <button>Banana</button>
    <button>Mango</button>
    <button>Grapes</button>
</div>
```
- target - if we want to know which button did the user actually click or which element does pull the trigger exactly.
- If we click Apple button then target = <button>Apple</button>
- currentTarget - if we want to know which element was handling my event function.
- currentTarget = <div onClick={handleClick}>

**Usually typescript can infer the event**
- You don't always need to explicitly type the event like: event: MouseEvent<HTMLButtonElement>
- for example:
```tsx
function App(){
    return (
        <input onChange = {(event) => {
            console.log(event.target.value);
        }}>
    );
}
```
- Typescript knows that event belongs to the inputs onChange handler.
- Explicit typing becomes useful when you create the handler seperately like another function inside main function.
