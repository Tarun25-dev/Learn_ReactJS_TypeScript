#### useImperativeHandle
- We already learned how a parent can access a DOM element inside a child using forwardRef through ref.
- Instead of exposing the entire DOM element, the child can decide exactly what the parent is allowed to do.
- It is only used for imperative actions.
- Thats what useImperativeHandle is for:

**Problem**
- With forwardRef the parent can directly access the input.
```tsx
inputRef.current?.focus();
inputRef.current?.select();
inputRef.current?.value;

```
- But sometime we don't want to expose the whole DOM element.
- We might want the child to expose only specific actions.
- The parent should't need to know how the child implements those actions.

**useImperativeHandle**
- Basic syntax:
```tsx
useImperativeHandle(ref, ()=> ({
    // Methods exposed to parent
}));
```
- First define what the parent is allowed to access:
```tsx
type InputHandle = {
    focus: () => void;
    clear: () => void;
};
```
- Child component or CustomInput
```tsx
const CustomInput = forwardRef<InputHandle>(function CustomInput(_, ref){
    const inputRef = useRef<HTMLInputElement>(null);

    useImperativeHandle(ref, () => ({
        focus(){
            inputRef.current?.focus();
        },
        clear(){
            if(inputRef.current){
                inputRef.current.value = "";
            }
        }
    }));
    return(
        <input ref = {inputRef} placeholder={Enter your Name}/>
    );
})
```
- Now the parent doesn't receive the input DOM element.
- Instead it recieves focus() and clear() methods.

- Now parent access those DoM element for particular actions decided by child:

```tsx
function App(){
    const inputRef = useRef<InputHandle>(null);
    return(
        <>
            <CustomInput ref={inputRef} />
            <button onClick = {() => inputRef.current?.focus()}>Focus</button>
            <button onClick = {() => inputRef.current?.clear()}>Clear</button>
        </>
    );
}
```
