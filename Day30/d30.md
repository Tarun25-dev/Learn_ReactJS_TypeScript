#### custom hook with localStorage

- creating hook that keeps react state synchronized with browser localStorage.
- This is useful for things like:
- Dark/Light theme preference
- saved settings
- shopping cart data
- Draft from data
- user preferences

**Problem**
```tsx
const [name, setName] = useState("");
```
- If you refresh the page then name was gone.
- Beacuse React state exists only while the page is running.
- But localStorage survives a refresh unless we close that tab completely.

**localStorage custome hook**
```tsx
import {useEffect, useState} from "react";

function useLocalStorage<T>(key: string, initialValue: T){
    const [value, setValue] = useState<T>(() => {
        const storedValue = localStorage.getItem(key);

        if (storedValue === null){
            return initialValue;
        }
        return JSON.parse(storedValue) as T;
    });

    useEffect(() => {
        localStorage.setItem(key,JSON.stringify(value), [key, value]);
        return [value, setValue] as const;
    });
}
```
- localStorage.getItem(key) The browser looks inside localstorage for the value refering by key.
- after that we need to check that value is null or any value beacuse as iniyially value isb't stored there may be stored as null.
- If browser finds any value for the key then it converts that all info into string like JSON.parse(storedValue) and that value we save as in T and that what type of the initialValue.
- Whenever the dependency array changes [value, setValue] then useEffect will run and updates the values in local storage.
- localStorage.setItem is used to update the data that already stored in localstorage.
- that return value not only update in localstrogae we need to show that in ui so we return [value, setValue] 
- hook returns two things that is value and setValue 
- why as const beacuse that the values are positioned at their place only like tuple then only we keep that values correctly.
